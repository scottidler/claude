# Implementation notes: rule routing

## Phase 1: Routing data
### Design decisions
- `load:` inserted as the last key inside each rule's existing frontmatter block — HOME/repos/.claude/rules/*.md — no other frontmatter or body line touched; `always` x7, `native` x8, routed objects x4 per the Data Model classification table.
- Routed triggers transcribed from the "Routed triggers" table with the table's `\|` unescaped to `|` (the backslash only escapes the markdown table cell) — git.md, marquee.md, otto.md, voice.md — regexes are single-quoted YAML scalars so `\b` and `\.` stay literal.
- voice and git `prompt` are one single-element list holding the table's alternation regex, kept verbatim rather than split into one entry per alternative — voice.md, git.md — same match semantics, closest to the table.
- git's `tools` after-entry and gate-entry are separate list items; bash `after` entries are bare strings, gates are `{ match, gate: true }` — matches the Data Model syntax.
### Deviations
- None.
### Tradeoffs
- Single alternation regex vs. one list entry per alternative for `prompt` — table fidelity won; Phase 2's parser treats both identically.
### Open questions
- None. (Note for Phase 2: voice's `\bPR\b` is matched case-insensitively per the Data Model, so it also matches the word "pr".)
- Criterion outputs: `rg --files-without-match '^load:' HOME/repos/.claude/rules/*.md | wc -l` printed `0`; all 19 frontmatter blocks parse with a YAML loader and every bash regex compiles.

## Phase 2: Router library
### Design decisions
- Hand-written YAML subset parser for `load:` (scalar `always`/`native`, a block map of `prompt`/`tools`/`bash` whose values are flow values or `- item` lists, flow `[...]`/`{...}`, single- and double-quoted scalars, ` #` comments) — rules.ts:parseLoad, Flow, blockMap — rails has no package.json and runs inside the engine's worker, so no YAML dependency; anything outside the subset (a multi-line block-map item, an unterminated flow, an unknown key, a non-boolean `gate`) throws instead of being misread.
- `parseLoad` compiles every regex (case-insensitive) and rejects a trigger map with zero triggers — rules.ts:validate — a rule that parses also matches; a routed rule with no triggers would never load, so that is a parse error, not a silent drop.
- `buildIndex(files)` indexes a rule whose `load:` is missing or broken as `always` with the reason in `error` — rules.ts:buildIndex — the doc's run-time rule (stays in context, caller names it on the status line); the CI teeth are the live-dir test asserting no `error` on any rule.
- `splitInstructions` part body runs from the end of its header line to the next header, so it carries the blank-line separator; the preamble is `{ header: '', body }`; a header must start the text or follow `\n\n`; no header at all throws — rules.ts:splitInstructions — join is plain concatenation (byte-exact), dropping any middle section leaves a well-formed blob, and a framing change fails loud (the risk table's "split failure throws -> latch").
- Header regex accepts `Contents of /abs/path (<tier>):` and `Contents of <...> (<tier>):`; the `<managed-settings>` section carries no `path` — rules.ts:SECTION — per the API comment and Phase 0 (b).
- `nestedPath` accepts an optional ` (<tier>)` suffix — rules.ts:nestedPath — tolerant of the engine adding a tier to nested rows; the path still ends at the header line.
- `matchTool` reports a rule that both gates and rides as gate only — rules.ts:matchTool — once the gate delivers it, the after-inject is redundant.
- `normalizeStatement` strips leading `VAR=val`, `env` with its options (`-i`, `-u NAME`, `-C DIR`, `-S`, ...) and assignments, then git global options (`-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--config-env` take a value; any other leading `-...` such as `--no-pager` is dropped); words are quote-aware and rejoined with single spaces — rules.ts:normalizeStatement.
- Fixtures are JSON beside the tests: `hooks/fixtures/instructions-2b8aebe2.json` (transcript `:19`, `rendered[0].content` minus the `<system-reminder>` wrapper, 68,183 chars, plus `files[]` path/tier) and `hooks/fixtures/nested-e9ef7f18.json` (`:191-205`, 15 rows, same unwrap, 57,861 chars). The unwrap is what the hook receives (typings: the wrapper goes around what the chain answers; Phase 0 (b) saw `instructions` open on the preamble).
- The fixture tests key the index under the recorded rules dir (`/home/saidler/repos/scottidler/claude/HOME/repos/.claude/rules`) while reading this checkout's rule text — rules.test.ts:RECORDED_RULES_DIR — the transcripts carry absolute real paths; this keeps the tests valid in any clone.
### Deviations
- `matchTool(index, tool, input, split)` takes a fourth argument, the Bash statement splitter — same effect, correct seam: the doc says Bash matching runs "after rails' existing statement split", which lives in index.ts (`heads` + `segment`); rules.ts importing index.ts would cycle once Phase 3 imports rules.ts. Tests pass `internals.heads`/`internals.segment`.
- Extra exports beyond the API block: `frontmatter`, `buildIndex`, `ruleAt`, `isRouted`, and the `RuleIndex`/`IndexedRule`/`InstructionPart`/`ToolMatch` types. The API used `RuleIndex` without defining how it is built; Phase 3 needs these.
- The success criterion's "18 parts with a `path`" is met as 18 file sections, 17 with a `path` and the `<managed-settings>` section without one, plus the path-less preamble (19 parts). The API comment says managed parts carry no path and Phase 0 (b) says "18" counts file sections; the test asserts 19 / 18 / 17 and the section order equals `files[]`.
- The settings.json tool-name test reads names from `permissions.{allow,deny,ask}` heads and the PreToolUse/PostToolUse `matcher` strings (expanding `a|b` and `x(a|b)` groups), plus one built-in, `ToolSearch`, which settings.json never names. Without that one name voice's ToolSearch trigger could not pass.
### Tradeoffs
- Subset parser vs. a YAML library — no dependency, no loader risk, and an explicit refusal of shapes it does not know; costs ~150 lines.
- Separators in the preceding body vs. in the following header — keeps `header` the exact header line; the cost is a trailing `\n\n` if Phase 3 drops the last section (whitespace only).
- `ruleAt`/`isRouted` scan a 19-element array vs. a Map — the index stays plain data (the ledger lesson about `$.state`), and 19 is nothing.
### Open questions
- `normalizeStatement` does not strip `sudo`, `command`, `exec`, or a path-qualified `/usr/bin/git`; the doc does not ask for them. Should `sudo git push` reach the git gate?
- Criterion outputs (2026-10-09, `main` after `f6f8036`): `splitInstructions` on 2b8aebe2: `parts 19 sections 18 with path 17`, preamble `"Codebase and user instructions are shown below. Be"`, path-less headers `(preamble)` and `Contents of <managed-settings> (organization-managed policy instructions):`; `join byte-exact true len 68183`. e9ef7f18: `paths 15 routed [ "marquee.md", "otto.md", "git.md", "voice.md" ]`, outside the index `CLAUDE.md`, `logging.md`, `cli.md`. `bun test`: `239 pass 0 fail 382 expect() calls` (147 before). `otto ci`: exit 0, `✅ All CI checks passed!`. rules.ts/rules.test.ts are not yet in `.otto.yml`'s lint list (Phase 4); `rg '—'` over both finds none.

## Phase 3: Wire the hooks
### Design decisions
- The five hooks are registered first in `register`, ahead of the four Bash hooks, so routing judges the call the model wrote and its context lands outermost; with `rule_routing` false they still register and the first dispatch latches routing off (quietly, no status line) and calls `$.ui.invalidate('prompt.attachment')` — hooks/index.ts:register — that is how flipping the toggle restores the full load mid-session; the module reloads on a config change but `register` has no `$`.
- The ledger and latch are working copies in module memory (`Router`), written through to `$.state` on every change and read back once per module load — hooks/index.ts:newRouter, loadRouter, persist — every claim (undefined to pending, pending to delivered) is one synchronous step, so two calls in one batch cannot both take a rule; a `$.state` compare-and-set loop would need fresh reads inside one dispatch, which the typings say read "one moment".
- The router is top-level functions over an explicit `Router` object, not a closure object with methods — hooks/index.ts — `claude plugin validate` refuses `rr.method($, ...)` ("$ itself is passed as an argument"); it follows `$` only into plain module functions.
- `$.state` values are declared in a contract file, `types/index.d.ts`, named as `"types"` in plugin.json — types/index.d.ts — validate requires every `$.state` key in the manifest's contract; index.ts imports the ledger types from it, so the module-load test now also allows `../` relative imports.
- `kept` maps a real path to the fingerprint (FNV-1a of type + text) of the attachment that kept it — hooks/index.ts:decideFiles, fingerprint — the same attachment asked again (any plugin's `invalidate('prompt.attachment')`) must not drop its own files as duplicates, which would hide CLAUDE.md and every always rule.
- A deny from a routed hook's own guard is computed before `next`; after-context is appended to whatever `next` returns, `isError` included, and a `deny` from below releases the claimed rules (they never reached the model); a `prompt.submit` dropped below releases the same way — hooks/index.ts:register, releaseRules.
- A gated call that also matches after-triggers denies only; the after rules are claimed on the retry. `session.compact` clears the loop when `trigger !== 'precompute'` and the result carries `messages` (precompute's result carries messages but installs nothing, per the typings).
- Rejoin keeps the blob's own trailing newline run: dropping the last section strips the predecessor's dangling `\n\n` and re-appends exactly what the blob ended with — hooks/index.ts:rejoin — tested both ways (blob ending without and with `\n`).
- A nested_memory with no `Contents of <path>:` header throws (framing changed), which latches; an instructions blob that splits to nothing already throws in `splitInstructions`.
- Log lines: `rules: keep|drop <basename> (<reason>) <real path>`, `rules: inject <basename> (<prompt|tool>) <path>`, `rules: gate <basename> (deny|pending, deny <tool>) <path>`, `rules: delivered ... (turn.step)`, `rules: skip <name> (leads to no file) <path>`; debug log always, transcript too when `debug` is on — hooks/index.ts:say — basename first so the AC's `rules: drop git.md` greps literally, the real path after the reason to tell the two CLAUDE.md files apart.
- Hook tests live in `rails/tests/routing.test.ts` (the kit's `tests` include dir), so `bun test` in `hooks/` never sees them; every noun rails calls is answered by the test's own `on` hooks, which must return `{ value }` (a throwing mock is skipped and reads as "no implementation", so the forced failure answers `{ deny }`).
### Deviations
- `kept` is `{ [realPath]: fingerprint }`, not `string[]` — same dedupe, plus the re-ask case above, which the Data Model's list cannot tell apart.
- The deny always ends with the draft clause ("If your text changes after reading it, show Scott the new draft before sending."), not only when the conversation already showed a draft — the hook cannot tell reliably whether a draft was shown; the clause is harmless when none was.
- Rule-index entries whose link leads to no file are skipped (debug line `rules: skip`), not read — found live: `~/repos/.claude/rules/cli.md` and `logging.md` are dangling links since `ba21860` moved both to `refs/`; the first headless smoke run read cli.md, got ENOENT, and latched the router off. The engine loads nothing from a dangling link either.
- The `instructions` and `nested_memory` real paths come from `$.fs.stat(path, { resolve: true })`, falling back to the spelling when it cannot resolve (cached per path for the module's life).
- The kit test's rule index is synthetic (the real classification, stub bodies) and the e9ef7f18 burst is its 15 recorded paths with stub bodies: the kit runs with no file system and imports only `.ts`, so it cannot read the JSON fixtures. The recorded text runs through the same `decideFiles`/`rejoin` under bun in index.test.ts.
### Tradeoffs
- Module memory plus `$.state` write-through vs `$.state` alone with `ifVersion` — atomic claims with no retry loop; costs one full-ledger write per change (a few KB at most).
- Latch on any `$.state` write failure vs best-effort persistence — a failed write is a router failure like any other, and the latch's direction (full load) is the safe one.
- Kit tests in `rails/tests/` vs a bunfig ignore pattern under `hooks/` — no extra config file, and it is the layout the typings' tsconfig names.
### Open questions

- `~/repos/.claude/rules/cli.md` and `logging.md` are dangling links (manifest left them after `ba21860`). Routing now skips them, but they should be removed from the deployed dir.

## Phase 4: Tooling
### Design decisions
- Runner split by suffix: the bun files are `hooks/index.spec.ts` and `hooks/rules.spec.ts` (`git mv`), the engine kit sees only `tests/routing.test.ts` - .otto.yml:test - `bun test` discovers `.spec.ts`, the kit's `*.test.ts` glob does not, so neither runner meets the other's files.
- The `test:` task runs `bun test` in `rails/hooks`, then `claude plugin test` on rails, then the existing `claude plugin validate --strict`; `set -e` makes either runner's failure fail CI.
- hooks-preflight.sh warns on an explicit off only: `enabledPlugins["rails@skills-dir"] == false`, `pluginConfigs.rails.options.enabled == false`, or `...rule_routing == false`; an absent key is enabled, per plugin.json defaults - HOME/.claude/hooks/hooks-preflight.sh - the all-present fixture must stay silent and rails loads as a skills-dir plugin with no `enabledPlugins` entry at all. The routing warning is its own sentence, separate from the unresolved-hook one, so the `manifest -l` fix hint does not trail a rails warning.
- Three fixtures added to hooks-preflight-test.sh (one per off-switch).
- CLAUDE.md: voice, git, otto relabelled `(on trigger)`; one bullet added after the otto line naming the four routed rules and the `load:` frontmatter.
### Deviations
- None against the spec. The doc says "when `rails` is not enabled"; the install enables rails as `rails@skills-dir` implicitly, so "not enabled" is read as an explicit `false`.
- Beyond the spec: the preflight test file gained the three fixtures; stale references to `rules.test.ts` in comments in `tests/routing.test.ts` and `index.spec.ts` were renamed.
### Tradeoffs
- Suffix partition vs. a bunfig ignore or running the kit on a copy - no extra config file, and each runner's default discovery is correct.
- Explicit-false check vs. requiring a positive `enabledPlugins` entry - the positive check would warn on every session on this install.
### Open questions
- Writing under `HOME/.claude/skills/rails` and `HOME/.claude/CLAUDE.md` required the authorized unsandboxed retry (`git mv`, the comment fixes, the CLAUDE.md edit).
- Observed (2026-10-09): `otto ci` exit 0, `All CI checks passed`; `claude plugin test` on rails exit 0, `15 pass 0 fail`, `Ran 15 tests across 1 file`; `bun test` in rails/hooks `262 pass 0 fail`, `Ran 262 tests across 2 files`; `rg -c rule_routing HOME/.claude/hooks/hooks-preflight.sh` prints `2`; hooks-preflight-test.sh `pass=11 fail=0`.

## Phase 5: Live acceptance
### Design decisions
- Every live check was a fresh headless `claude -p --debug-file <scratch>` session (CC 2.1.296), the evidence being the router's `rules: ...` debug lines and the engine's own `left it out` / `resolved by a hooks module` lines, never the model's self-report - Scott's ruling for this phase.
- The criterion 3 prompt spelled "slack" out letter by letter. A first run that wrote the path literally in the prompt fired voice's prompt trigger (`rules: inject voice.md (prompt)`), which is correct routing but not the replay the criterion describes. The burst in that run was the same 4 drops and 9 keeps (the later `drop voice.md` is the duplicate of the already-injected rule).
- A Bash `cat` of a glob (`refs/s?ack.md`) raised no `nested_memory` burst at all: the engine only counts a `cat` of a literal path as a read under `~/repos`. The recorded run uses the literal path.
- Canary for the inject path: the date in git.md's "Just yeet it." parenthetical, which appears nowhere else in the loaded context. Control session (no tool call) answers `NONE`; after one `git -C ... log -1` it answers `2026-07-03`.
- Live sessions ran unsandboxed: inside the Bash sandbox the nested `claude`'s shell snapshot fails (`EROFS ... session-env`), so its first Bash call errors before the command runs.
### Deviations
- Criterion 4 amended (doc defect, independent of the code): it named `git tag -l` as the inject trigger, but the doc's own routing table (git row, and the frontmatter example `{ match: '^git (push|tag|branch -D)\b', gate: true }`) makes `git tag` a gate hit. Any implementation of the spec denies it, it is never injected. Observed: `rules: gate git.md (deny Bash)`, then `rules: delivered git.md (turn.step)`. The criterion now uses `git -C <repo> log -1` and `git -C <repo> status`. `-C` because `~/repos` is not a git repository and `git-release-guard.sh` denies a bare git command there (`'/home/saidler/repos' is not a git repository`).
- Criterion 3 amended from "cli and logging do not appear at all" to "have no keep or drop line". `~/repos/.claude/rules/cli.md` and `logging.md` are still symlinks to `HOME/repos/.claude/rules/{cli,logging}.md`, which `ba21860` moved to `refs/`. Both dangle, the engine loads neither, and the router's index logs each once: `rules: skip cli.md (leads to no file) /home/saidler/repos/.claude/rules/cli.md`. That is deployment state (the symlinks were not pruned), not router behaviour.
### Tradeoffs
- Amend the two criteria vs. stop and report: both failures are provable from the doc text and the filesystem alone, and the run-as-written results are recorded beside the amended text, so nothing about the code's behaviour is hidden.
- Headless `-p` runs vs. interactive `claude --debug`: no human in the loop and reproducible, but one turn per process, so "fresh session" is literally a fresh process per check.
### Open questions
- The dangling `~/repos/.claude/rules/cli.md` and `logging.md` symlinks should be pruned (manifest/link cleanup, system-mutating, not done here). Once they are gone the `skip` lines disappear and criterion 3's original "do not appear at all" holds.
- Observed (2026-10-09): criteria 1 `0`; 2 `bun test` `262 pass 0 fail`, `claude plugin test` rails `15 pass 0 fail`; 5 `rg -c rule_routing` `2`. Criteria 3 and 4 lines quoted under each criterion in the design doc.
