# Hub hygiene

cortex's auto-linker treats every entity-hub stem as a link target. When the stem
is an ordinary English word, every prose occurrence becomes a wikilink: noise in
the note, a false edge in the graph, and nothing to click through to.

Fixing it one word at a time (append to `graph.wikilink-stopwords` after the
damage) is what let `[[every]]`, `[[brief]]`, and `[[database]]` each spray across
hundreds of notes. This skill replaces that with a measurement.

Background and the current verdict table: `notes/entity-hub-linkability-audit.md`
in the vault.

## The predicate

For each single-token hub name, count prose occurrences (excluding frontmatter,
fenced code, indented code, and existing wikilink markup) and split by casing:

```
proper-noun ratio = capitalized non-sentence-initial / (that + lowercase)
```

- not an English word -> **KEEP** (`sqlite`, `karpathy`, `ollama`)
- fewer than 5 prose uses -> **KEEP** (no evidence)
- ratio >= 50% -> **KEEP** (`Claude` 76%, `Kubernetes` 91%, `Offense` 55%)
- ratio <= 20% -> **PURGE** (`security` 6%, `workflow` 7%, `every` 12%)
- in between -> **REVIEW** (ask; `github` is a legitimate keep whose ratio is
  depressed by `github.com` in URLs)

Multi-token hubs (`rule-of-five`, `handmade-network`) are unambiguous by
construction and are not audited.

Do NOT substitute a shortcut that looks equivalent:

- ontotype is not the signal: `every` and `brief` are `ontotype: creator`
- a dictionary alone is not the signal: `Rust`, `Obsidian`, `Redis`, `Signal` are
  dictionary words and unambiguous proper nouns here
- corpus frequency alone is not the signal: `Claude` is the most frequent word in
  the vault and the most useful hub

## Workflow

### 1. Audit (read-only, always start here)

```bash
python3 ~/.claude/skills/hub-hygiene/scripts/hub_audit.py \
    --vault ~/repos/scottidler/obsidian \
    --json /tmp/hub-audit.json
```

Prints PURGE / REVIEW / KEEP with inbound link counts, prose counts, ratio, and
stub status. Present the PURGE and REVIEW rows to the user with the numbers; never
purge a REVIEW row without an answer.

### 2. Stoplist the confirmed purges

Add each name under `graph.wikilink-stopwords` in `~/.config/sb/cortex.yml` (the
real file lives in the dotfiles repo; edit there, never the symlink). One list,
three consumers: `linking` refuses to write, `graph` refuses to mint the edge,
`unlink` retracts what landed.

### 3. Retract what already landed

```bash
sb cortex unlink              # report first, always
sb cortex unlink --apply      # then write
```

Scope note: the sweep deliberately skips authored notes, hub bodies, code spans,
and indented blocks, because the linker never wrote there. A `[[word]]` left in a
code span or a hub's own self-description is correct, not a miss.

### 4. Prove it sticks

```bash
sb cortex link --apply && sb cortex unlink
```

A link pass followed by a clean `unlink` report is the difference between this and
a hand retraction: it demonstrates the writer is gated, not just the vault
cleaned. Two previous attempts skipped this step and the links returned on the
next daemon tick.

### 5. Commit

The vault is a git repo with a live daemon writing into it. Commit the retraction
as its own change, grouped by kind, and do not leave the tree dirty:

```bash
cd ~/repos/scottidler/obsidian && git add -A notes entities && git commit
```

## Hub notes themselves

Stop linking; do not delete. Hubs are derived artifacts regenerated by
`sb cortex hub` from member claims, so deleting one just means the next hub pass
re-stubs it, and the hub is still a useful tag-bundle view. The thing worth
deleting is the markup, not the note.

The exception is a mis-typed entity - an ordinary noun carrying
`ontotype: creator` (`syntax`, `football`) - which is a data error worth fixing at
the source.

## Known gap

There is no minting gate yet. `sb cortex hub` will stub a hub for any dense tag,
which is exactly how `database` appeared and immediately spread to 113 notes. Until
that gate exists in cortex, run this audit after any `sb cortex hub --apply` and
after adding a batch of notes on a new topic.
